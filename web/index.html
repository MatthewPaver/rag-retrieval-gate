What does this test tell us?

The check asks whether labelled evidence is found and how highly it ranks. Finding the right policy somewhere in the results is different from putting it first.

This example compares 11 illustrative documents and 6 questions. It uses a 0.02 absolute drop threshold with the statistical significance check off. That makes it a small smoke test, not an accuracy benchmark.

A pass means no regression was detected under these settings. It does not prove an improvement, a safe release or correct generated answers. The existing refund result already puts an ended pilot first.

A check before the change.

  1. Choose questions that matter.

    Use questions your staff ask. Label which documents support each answer, including conflicting or outdated guidance.

  2. Compare the two versions.

    The engine runs the same questions against your current and proposed search settings. It records the evidence each version finds.

  3. Review what moved.

    Inspect source order, missing context and measured drops. Keep the report with the proposed change.

Set up the gateDownload the labelled example
Engineer setup and test settings

Clone the repository and run these commands from its root:

python -m pip install -e .
rag-gate gate --dataset fixtures/policies.json --k 3 \
  --baseline configs/baseline.json \
  --candidate configs/candidate-chunk-12.json \
  --no-bootstrap --output reports/comparison.json \
  --html reports/report.html

The deliberate regression returns exit 1. Replace the fixture with your labelled questions and documents, and choose the configs before testing. Do not tune on the test questions.

For a representative evaluation, remove --no-bootstrap. The default gate requires both a drop over 0.02 and a paired 95% bootstrap interval excluding zero. Invalid or incomparable input gives no verdict and exit 2.

Core retrieval uses Python’s standard library. Optional dense models require separate installation and explicit permission to download.
